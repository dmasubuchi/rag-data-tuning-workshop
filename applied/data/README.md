# 応用編で使う採用の文書

このフォルダーのデータは、すべて**研修用の架空データ**です。会社（サンプルテック）、人物、メールアドレス（`*.example`）、電話番号は実在のものと関係ありません。

応用編では、形式の違う文書をまとめて取り込み（インデクサーとスキルセット、OCR）、求人・応募・評価をまたいで探します。件数は少なく、同じ人・同じ求人の番号で書類どうしがつながっていることを大事にしています。

## 入っているもの（23 ファイル）

- `jobs/`：求人票 PDF 3 件。文字が入っている PDF
  - `JOB-REQ042-v3.pdf`（バックエンドエンジニア（プロダクト開発））、`JOB-REQ043-v1.pdf`（バックエンドエンジニア（決済基盤））、`JOB-REQ047-v2.pdf`（SRE エンジニア）
- `resumes/`：職務経歴書 Word（.docx）6 件。`CV-APP-<応募番号>.docx`
- `evaluations/`：面接の評価 Excel 1 件。`EVAL-INTERVIEWS-2026-10.xlsx`
  - シート：面接評価（12 行）、選考状況、選考履歴、評価基準、注記
- `mail/`：面接の連絡メール（.eml）10 件。`MAIL-<通し番号>_<求人番号>_<応募番号>.eml`
- `scans/`：スキャンした書類 3 件。**画像だけ**で文字の情報は入っていない（OCR が必要）
  - `SCAN-MEMO-APP-0391-2ND.pdf`：面接官の手書きメモ
  - `SCAN-OFFER-APP-0386.pdf`：内定承諾書（押印あり）
  - `SCAN-COVER-APP-0471.png`：紹介会社の書類送付状（FAX 風）
- `manifest.json`：全ファイルの種類、対象の求人・応募・人物の番号、元にしたデータ、応募ごとの書類の一覧
- `updates/`：トピック 17（更新と削除）だけで使う、求人票の旧い版。`JOB-REQ042-v1.pdf`（REQ-042 の v1。現行は v3）。上の 23 ファイルには数えない。manifest にも入れず、`build_hr_index.py` も Storage に置かない。17 が、チームの `jobs/JOB-REQ042-v3.pdf` を一時的にこの v1 の中身で上書きし、v3 で上書きして戻す
- `_build/`：このフォルダーを作ったスクリプトと、その入力

## 番号でつながる

- 求人番号 `REQ-nnn`：求人票・職務経歴書・面接の評価・メール・スキャンに共通
- 応募番号 `APP-nnnn`：1 回の応募。職務経歴書・面接の評価・メール・スキャンに共通
- 人物キー `C-nnn`：同じ人の別の応募をつなぐ番号（Excel の「人物キー」列、manifest）
- 評価番号 `EV-nnn`：Excel「面接評価」シートの 1 行
- 面接官など社内の人は `U-nnnn`（Excel の「面接官ID」）

## 注意

- 選考の日付・段階・状況は、manifest の `applications` と Excel の「選考状況」「選考履歴」が基準です。評価の実施日時は選考履歴の「面接実施」と同じです。
- Excel の「提出状況」が「下書き（未提出）」の行は、確定した評価ではありません。
- `jobs/` の求人票の PDF は現行の版だけです。応募には応募時の版（`req_version`）が付いています。旧い版は `updates/` にある REQ-042 の v1 だけです（台帳 `_build/content/source_ats.json` の REQ-042 v1。有効期間 2026-09-01 〜 2026-10-13）。
  - v1 と v3 は、検索で見分けられる違いがあります。年収（v1 は 500万円から700万円、v3 は 600万円から800万円）、勤務（v1 は週4日出社・リモート週1日まで、v3 は週2日出社・リモート週3日まで）、「試用期間」「入社後の流れ」（v1 にだけある）、歓迎条件（v3 に「障害対応の一次切り分けの経験」が加わる）。v1 は文章が長く、取り込むとチャンクが 3 件、v3 は 2 件になります。
- このフォルダーのファイルは、Azure に何も登録していません。構築する人が `applied/tools/build_hr_index.py` で Storage に置き、インデックス `hr-docs` に取り込みます。

## 作り直し方

入力はすべて `_build/content/`（求人票の旧い版は `_build/content/updates/`）にあります。仮想環境（Python 3.12）に `_build/requirements.txt` を入れて実行します。**作り直すには macOS が要ります**（下の注意）。文書そのものは、作り直さなくても、この Repo にあります。作り直すのは、教材を直す人だけです。

```
python _build/build_all.py            # 作り直して manifest.json を書き、検査する
python _build/build_all.py --verify   # 2 回作って、全ファイルが同じバイト列になることを確かめる
python _build/check_all.py --ocr      # 検査だけ。tesseract があればスキャンの OCR も試す
python _build/selftest_check.py       # 検査の自己試験。既知の誤りを 1 つずつ入れて、検査が見つけることを確かめる
```

- `check_all.py`（`build_all.py` と `selftest_check.py` も）は、使ってはいけない語（固有名）の一覧を、環境変数 `PUBLIC_CHECK_BANNED` が指すファイルから読みます（Repo 直下の `tools/check_public.py` と同じ形。1行1語、UTF-8）。一覧はこの Repo に置きません。変数がない・ファイルがない・空のときは、説明を出して終了コード 2 で止まります。見つけたときは、語そのものは出さず、「禁止語の一覧の 3 番目」のように番号で知らせます。自己試験は、架空の語の一時の一覧を自分で作って使います

- 検査（check_all.py、中身は check_identity.py）は、全ファイルと `updates/` の旧い版の求人票を読み直して、応募番号・氏名・求人番号・宛先・日付・担当者が台帳（`_build/content/source_ats.json`）と食い違っていないかを調べます。メールの宛先と本文、経歴書、評価、スキャンの書類が別の応募のものになっていれば NG にします。
- 時計・ネットワークは使いません。乱数は seed を固定しています。
- 日本語の PDF は reportlab の CID フォント、スキャンの手書き風の文字は macOS のフォント（ヒラギノ、Klee）で描いています。macOS 以外では描画に使うフォントが見つからず、作り直せません。
- 職務経歴書（Word）のフォントは「游明朝」です。
