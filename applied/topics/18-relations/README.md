# 18 関係で探す（紹介）

「REQ-043 に応募した人の、面接の評価の推奨は？」のような質問は、書類をまたいで、関係をたどらないと答えられません。
求人 → 応募した人 → その人の職務経歴書・面接の評価、です。このトピックは紹介です。
番号（ID）で2〜3段たどる方法と、1回の検索で試す方法を比べます。

## 何を学ぶか

- 採用の文書には、つなぎの番号がある
  - 求人番号 `req_id`（REQ-043）：求人票・経歴書・メール・スキャン
  - 応募番号 `application_ids`（APP-0386）：経歴書・メール・スキャン、面接の評価の本文
  - 人物キー `person_keys`（C-115）：同じ人の別の応募をつなぐ番号
- 番号を欄で絞って、1段ずつたどる
  1. 求人票：`kind eq 'job_posting' and req_id eq 'REQ-043'`
  2. 応募：`req_id eq 'REQ-043'` の、求人票以外の文書にある `application_ids` を集める
  3. 経歴書：`kind eq 'resume' and search.ismatch('APP-0386', 'application_ids', 'simple', 'any')`
  4. 面接の評価：評価の Excel のチャンクのうち、本文に `APP-0386` が出てくるものから、評価の行（評価番号・段階・推奨）を読む
- 1回のハイブリッド検索は、意味が近い文を集めるだけ。「この求人に応募した人」という関係を知らないので、足りない評価と、余計な評価が出る
- 絞り込みは、16 の採用担当の立場（`allowed/any(a: search.in(a, 'role:recruiter'))`）。応募を横断して比べるので、採用担当の立場で実行する（面接官は、担当する応募の評価だけ見える。16）

## 前提

- `pip install -r applied/requirements.txt`（Repo 直下で、仮想環境の中で）
- 構築する人がインデックス `hr-docs` を作り、見てよい人（`allowed`）を付けてあること（なければ構築する人に聞く）
- メンバーの設定（検索だけのキー、Storage なし）で動きます

## 実行

```
python trace_relations.py                  # REQ-043（応募 1 件、評価 3 行）
python trace_relations.py --req REQ-042    # 応募 5 件、評価 7 行
python trace_relations.py --req REQ-047    # 応募 1 件、評価 2 行
```

## 見るところ

- 「0. 目録」：`manifest.json` が、応募ごとの書類と評価番号を持っている。実際の業務では、採用管理システムのデータベースにあたる
- 「1. たどる」の表：段ごとに、絞った欄（filter の式）と、見つかったもの。前の段で見つけた番号が、次の段の式に入る。検索は 4 回（応募が何件あっても同じ）
- 「たどった結果」：応募ごとに、評価番号・段階・推奨が決まって出る。最後に、目録の評価番号と同じかを確かめている
- 「2. 1回の検索」：上位 5 件のチャンクに、欲しい評価の行が全部は出ず（REQ-043 では 3 行のうち 1 行）、別の求人の応募のチャンクが混ざる。表の「方法」の比べで、答えが決まるのはたどる方法だけ
- REQ-042 は、応募 APP-0439 が、経歴書もメールもなく、面接の評価の Excel にだけ出てくる。「目録にだけある応募」と出て、評価は下書き（未提出）。欄だけでは見つからず、本文の番号で見つかる
- 評価の Excel は、応募番号が文書ぜんたいの欄に、6 件分まとめて入っている。このため、欄では絞れず、本文の応募番号で探している。欄の付け方で、たどり方が変わる

## 発展：GraphRAG・オントロジー（紹介だけ。実装しない）

ID をたどる方法は、たどる段数・関係の種類が少ないうちは、これで足ります。関係が多く、深くなると、たどる処理を自分で書くのが大変になります。そのときの考え方が2つあります。

- GraphRAG：文書から、人・求人・組織・出来事などの「もの」と、その「関係」を LLM で取り出して、グラフ（点と線）にする。質問に答えるときに、グラフで関係をたどり、関係のまとまりの要約も使う。ID が欄に付いていない文書（メールの文面など）から関係を取り出せる反面、取り出しに LLM を使うので費用と時間がかかり、取り出し方を確かめる必要がある
- オントロジー：「求人」「応募」「面接の評価」などの種類と、その間の関係（応募は1つの求人に属する、評価は1つの応募に属する、など）を、先に決めておく。データをその決まりに合わせて持つので、たどる質問を、決まった形で書ける。決まりを作る手間がかかる
- 目安：この教材のように、関係を示す番号がデータに付いていて、たどる段数が少ないなら、欄で絞る方法がまず手軽。番号がなく、文書の中の関係を探したいなら GraphRAG。関係の種類が多く、業務の決まりが固まっているなら、オントロジー
- 18 は、ここまでの紹介です。コードで試すのは、番号をたどる方法だけです
