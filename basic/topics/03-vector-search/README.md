# 03 ベクトル検索

## 学ぶこと

- 文を埋め込み（数の並び）にして、意味が近い文書を探す
- 質問と本文の言葉が違っても、意味が近ければ見つかる（キーワード検索が外れた質問で確かめる）
- ベクトル検索も万能ではない。スコアは方式のあいだで比べない

## 前提

- `../01-keyword-search` が終わっていること（武将のインデックスと、登録した武将）
- `embed.py` は、AI Search の管理者キーが要るので、構築する人の設定（`--role builder`）で実行する。メンバーの設定（検索だけのキー）では、「構築する人の設定で実行します」と止まる。`vector_search.py` は、メンバーの設定でもできる
- 足りないときは、`python ../../tools/reset.py --to 03`（スクリプトの先頭の `REBUILD = True`、スクリプトでは `--rebuild` でも作り直せる。Notebook では、作り直したら `REBUILD = False` に戻す。`True` のままだと、実行のたびに作り直す）

## 実行するコマンド（このフォルダで）

必須（この順に）
- `python embed.py`　ベクトルの項目を足し、武将を埋め込んで登録する（Azure OpenAI で埋め込む）
  - 時間が足りないときは `python embed.py --use-file`（同梱の埋め込み済みファイルを使う）
  - 登録のあと、ベクトルが検索に出てくるまで待つ（反映に少しかかる。30秒で揃わなければ止まるので、少し待ってもう一度実行する）
- `python vector_search.py`　01 の `search_paraphrase.py` と同じ質問を、ベクトル検索で実行する

発展
- `python peek_vector.py`　埋め込んだ数の並びの最初の 10 個と、質問との近さ（コサイン類似度）

Notebook でも、同じファイルを上から順にセルで実行できます。`--q` などの引数に当たるものは、先頭の「変えてよい値」のセルの変数（`QUESTION`、`USE_FILE = True` など）で指定します。

## 何を見ればよいか

- `embed.py`：インデックスにベクトルの項目（`profile_vector`、1536 次元）が足される。セマンティックランカー用の設定も、ここで足す（04 で使う）
- `vector_search.py`：同じ質問で、正解の武将の順位がキーワード検索と比べてどう変わるか
- `peek_vector.py`：数の一つひとつに意味はなく、向きの近さだけが意味の近さの目安

## 演習

- `vector_search.py --q "自分で考えた言い換え"` で、キーワードとベクトルを比べる
