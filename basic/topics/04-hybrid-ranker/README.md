# 04 ハイブリッド検索とセマンティックランカー

## 学ぶこと

- キーワード検索とベクトル検索を、1回の呼び出しで両方使う（ハイブリッド）。順位は RRF（順位の逆数の合計）で決まる
- セマンティックランカーは、前段の上位の候補を、質問と本文の意味を読んで並べ直す
- 同じ質問の正解の順位を、4つの方式で並べて比べる。方式の優劣は、質問によって変わる

## 前提

- `../03-vector-search` が終わっていること（武将にベクトルが入っていること）
- 検索だけなので、メンバーの設定（検索だけのキー）でも実行できる（05・06 も同じ）
- 足りないときは、`python ../../tools/reset.py --to 04`（スクリプトの先頭の `REBUILD = True`、スクリプトでは `--rebuild` でも作り直せる。Notebook では、作り直したら `REBUILD = False` に戻す。`True` のままだと、実行のたびに作り直す）

## 実行するコマンド（このフォルダで）

必須（この順に）
- `python hybrid_search.py`　ハイブリッド検索（キーワード ＋ ベクトル）
- `python rrf.py`　RRF の計算の途中を表示し、AI Search の順位と照合する
- `python ranker.py`　ハイブリッドにセマンティックランカーを付ける（ランカーを 1 回使う）
- `python compare_methods.py`　同じ質問の正解の順位を、4つの方式で並べる（ランカーを 1 回使う）

質問は、`QUESTION = None` のとき、`data/sengoku/selection.json` で選んだ山場の質問（q53）を使う。自分の質問は `--q "…"`。

Notebook でも、同じファイルを上から順にセルで実行できます。`--q` などの引数に当たるものは、先頭の「変えてよい値」のセルの変数（`QUESTION` など）で指定します。

## 何を見ればよいか

- `rrf.py`：自分の計算の順位と、Azure の列（AI Search の順位）が合うか
- `ranker.py`：ランカーなしのハイブリッドと、ランカーありの正解の順位
- `compare_methods.py`：4つの方式の表。「方式を変えれば必ず良くなる」わけではない

## 演習

- `rrf.py` の `RRF_K = 60` を `10` にする：自分の計算の順位と AI Search の順位が合わなくなる。AI Search は定数 60 を使っている
- 発展：`rrf_table()` を自分で書き直す。`K`（ベクトル側の候補数）を変える
